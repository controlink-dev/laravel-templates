controlink/laravel-templates

Integration guide

A stateless toolkit for versioned, reproducible print templates in Laravel: an embedded GrapesJS editor, a pure compose → render → validate → hash pipeline, and a type catalogue. The host owns its own data, routes and lifecycle — this page is how to wire them.

0Quick start

One command scaffolds everything the host owns into the host's own paths — nothing is left inside the package:

composer require controlink/laravel-templates
php artisan templates:install
Generated fileWhat it is
app/Models/Template.php
app/Models/TemplateVersion.php		the two Eloquent models
database/migrations/…_create_templates_table.phpthe reference migration
app/Http/Controllers/TemplateEditorController.phpthe seven endpoints, implemented
routes/templates.phpthe routes, plus the urls prop example
app/Policies/TemplatePolicy.phpthe policy (denies everything until wired)

It also publishes the editor bundle (--tag=templates-assets) and config. It never overwrites an existing file — pass --force to replace — so re-running it is safe. Then:

// routes/web.php
require __DIR__.'/templates.php';
  1. Grant abilities in TemplatePolicy (it denies everything by default).
  2. Declare a type in config/templates.php.
  3. php artisan migrate.
The generated code is the reference implementation, not a black box — it is yours to adapt. Everything below is the contract behind each file.

1Models

The editor component takes any two Eloquent models. It never names a concrete class; it reads a fixed shape off them.

Template

use Controlink\Templates\Templates;
use Controlink\Templates\Types\TemplateType;

class Template extends Model
{
    protected $fillable = ['type_code', 'name'];

    public function type(): TemplateType
    {
        return Templates::type($this->type_code);
    }

    public function versions() { return $this->hasMany(TemplateVersion::class)->orderBy('number'); }
}

TemplateVersion

use Controlink\Templates\Models\Concerns\GuardsIssuableVersion;
use Controlink\Templates\Versions\VersionState;

class TemplateVersion extends Model
{
    use GuardsIssuableVersion; // freezes an active/archived version's layout

    protected $casts = [
        'state'        => VersionState::class,
        'project_data' => 'array',
        'geometry'     => 'array',
        'activated_at' => 'datetime',
    ];

    public function isEditable(): bool { return $this->state->isEditable(); }
}
GuardsIssuableVersion throws ImmutableVersionException if an active/archived version's layout (project_data, html, css, hash, number, template_id) is changed. The state and activation metadata stay writable, so activation and archiving still work.

2Version lifecycle

draft →save · static ✓ validated →activate · render ✓ active →another activates archived

Only one version per template is active. active and archived are issuable — an issued document points at the exact version that produced it — and therefore immutable. Editing an issuable version means cloning a new draft from it, never mutating it.

3HTTP endpoints

The component registers no routes. The host defines them and passes their URLs through the urls prop. The editor sends on every request: X-CSRF-TOKEN, X-Requested-With, Accept: application/json, and — when configured — a tenant header from TenantResolver::currentId().

EndpointVerbDoes
loadGETreturns { data: { project_data, html, css } }
savePUTlayer-1 (static) validation, then store as validated
previewPOSTrender the fixture, stream the PDF bytes (no state change)
activatePOSTlayer-2 (render) validation, then promote to active
catalogueGETthe editor's block/field catalogue for a type
stylesheetGETthe print stylesheet, raw (canvas and PDF read identical bytes)
fontGETone font file, by {family}/{weight}

Routes

Route::middleware(['web', 'auth'])->prefix('templates')->name('templates.')->group(function () {
    Route::get('{template}/versions/{version}/edit', [C::class, 'load'])->name('load')->scopeBindings();
    Route::put('{template}/versions/{version}', [C::class, 'save'])->name('save')->scopeBindings();
    Route::post('{template}/versions/{version}/preview', [C::class, 'preview'])->name('preview')->scopeBindings();
    Route::post('{template}/versions/{version}/activate', [C::class, 'activate'])->name('activate')->scopeBindings();

    Route::get('catalogue/{type}', [C::class, 'catalogue'])->name('catalogue');
    Route::get('stylesheet', [C::class, 'stylesheet'])->name('stylesheet');
    Route::get('fonts/{family}/{weight}', [C::class, 'font'])->name('font')->whereNumber('weight');
});

Passing the URLs to the component

The font URL must keep its literal {family}/{weight} placeholders — the component substitutes them per face — so it is built with marker tokens and swapped back, because route() URL-encodes real braces.

$urls = [
    'load'       => route('templates.load', [$template, $version]),
    'save'       => route('templates.save', [$template, $version]),
    'preview'    => route('templates.preview', [$template, $version]),
    'activate'   => route('templates.activate', [$template, $version]),
    'catalogue'  => route('templates.catalogue', $template->type_code),
    'stylesheet' => route('templates.stylesheet'),
    'font'       => str_replace(
        ['FAMILY_PLACEHOLDER', 'WEIGHT_PLACEHOLDER'], ['{family}', '{weight}'],
        route('templates.font', ['family' => 'FAMILY_PLACEHOLDER', 'weight' => 'WEIGHT_PLACEHOLDER']),
    ),
];
<x-templates::editor :template="$template" :version="$version" :urls="$urls" />
Geometry handed to the pipeline must carry the zone bands: the toolkit reads header/footer heights off geometry['zones'], and those live in the type's initial layout, not its pdf block. The generated controller folds them in for you.

3.1Error contract

Any non-2xx response is a failure; the editor reads JSON:

{ "message": "human-readable reason", "problems": [ /* optional */ ] }

Problem entries differ by layer, exactly as the toolkit returns them — pass them straight through:

LayerShape
static (layer-1){ code: "V-10", component_id, message }
render (layer-2){ code: "R-07", page, message }

4Authorization

Every endpoint authorizes through Gate::authorize(). Laravel auto-discovers the policy for the model (App\Models\Template → App\Policies\TemplatePolicy) — on Laravel 11+ there is no AuthServiceProvider to register. The generated controller extends Illuminate\Routing\Controller, since the app's base controller no longer carries the authorization trait on Laravel 10–13.

5Tenancy

The package owns no database and no tenancy mode. A multi-tenant host scopes its own models the way it scopes everything else. The one touch-point is the editor's optional tenant header — bind a TenantResolver and set templates.editor.tenant_header; the toolkit calls only currentId().

6Reproducibility conformance-kit

Mount Controlink\Templates\Testing\AssertsReproducibility in the host's test suite to prove the host's persistence kept the discipline the toolkit relies on: a stable input hash, an immutable issuable version, and a reproducible re-render.
